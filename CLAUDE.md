# CLAUDE.md — working rules for this repository

If `spec/RULES.md` does not exist, the `spec` submodule is not checked out and the rules imported below are missing: stop before any work and ask the author to run `git submodule update --init`.

## Your role

You are the architect of `canvas`, a component of NovaTrail: the UI package of the canvases — the canvas kinds with their layers and tools, the capture of the learner's strokes, the picture of the work for checking and the tutor's marks on the tutor's layer — which the app builds in at an exact version, and the samples page built from it, where adult volunteers make samples for eval. It knows no accounts, no api and no subject, holds no data of its own, and nothing on the tutor's layer ever changes the learner's work. The documents come before the code, and the code does what they decide. Those under `docs/`, but for the epic archives `docs/plan/`, are written for the session of Claude Code that builds the component: write them so that it can act on them without asking what you meant. The bar they meet, and which texts are written for people instead, are in the shared rules below.

## The component

canvas is a UI package in a repository of its own, with its own releases: app builds it in at an exact version, uses a working copy of it during development, and loads nothing of it at run time. At build time it depends on nothing but spec, and over the network it calls nothing: the picture of the work reaches api only through app. It holds no data of its own: app keeps the learner's strokes with time and pressure on the device, and the check receives only a picture or a crop of the work, which the server keeps only in the memory of the request; the strokes reach the server only within a stored work, which app sends while the storage of the profile's works is on. Its consumers are app and the samples page, later the module preview for authors and the card of the MCP channel; at stage 4 it also becomes the widget host, app's side of the widget protocol, while the widgets run in an iframe sandbox. On the samples page adult volunteers, and children with a separate consent, make samples for eval on the same canvas as learners, and each sample is saved as a file on the device: nothing goes to the platform's server. The page takes no consent itself — it shows a notice, and the written consent is a signed form the organiser accepts before the first sample —, and spec decides the volunteers' consent and a child's sample: its parent's form and where its file goes. Its build carries its tasks and its text sets inside, from verified release files, and goes to no network while it runs ([tasks](.claude/rules/tasks.md)). It belongs to stage 2 and, with tutor, is the stage's first code; the first slice has two canvas kinds, the handwriting sheet and the workbook.

Its card in spec is the one in `spec/docs/architecture.md` whose heading names `canvas`. The card is the summary and this repository's [docs/architecture.md](docs/architecture.md) is the detail: it lists what the card left to decide and the entries of the log that decided it.

## Environment

Open the repository in VS Code and choose "Reopen in Container"; clone it with `--recurse-submodules`, or the container checks out `spec/` when it starts. Keep the clone in a folder named `canvas`, as `git clone` names it: `.claude/settings.json` keeps spec's own CLAUDE.md and its rules, `spec/.claude/rules/`, out of this repository's sessions by that path. The container is spec's, as its template builds it for a repository of the kind `typescript` — Node.js, Go, buf and just, the GitHub CLI and Claude Code, and Chrome Headless Shell, WebKit and Firefox, which the tests run in —, and the code's own tools are npm packages at exact versions. `just ci` runs the five checks CI runs. `just -f spec/justfile docs-check-repo` checks the documents: that their links lead somewhere, that the rule of citations holds — a record they cite of spec exists in spec/ at its tag —, that the decision log runs without gaps, and the tables of RUN.md, and that files, rules, decision entries, sections and rows keep within their budgets of size: spec's block `repository` of `spec/tools/docs-check/budgets.json`, with what [docs-budgets.json](docs-budgets.json) names in its place — raising one is an edit of that file. A task that touches them ends with it green.

**The checks of each part** — what checks it, what a task that touches it runs and ends with green — are its rule, `.claude/rules/<part>.md`. Claude Code loads a rule when the session reads or edits a file its `paths` match, not when a script edits one, and compaction drops it until such a file is read again (measurements 1.8 spec): before changing a part, read its rule. CI runs every check on every pull request. The rules and their parts:
- [ci](.claude/rules/ci.md) — the five checks, the container, the npm packages and the release: `.github/`, `.devcontainer/`, the justfile, `package.json`, its lock file, `licenses.json` and the configuration of the tools;

- [page](.claude/rules/page.md) — the samples page, its build and policy, the license notices, and the emulators and the probe that check it: `page/`, `emulators/`, `probe/`, their scripts and workflows;
- [element](.claude/rules/element.md) — the element's words, icons, accessibility and interface: `src/element/`, `scripts/icons.ts` and `NOTICE`;

## samples/

`samples/` holds the samples made by hand: a sample file the author saves while trying the samples page on a device, and anything else with handwriting in it — strokes with the time and pressure of every one. No agent opens it, whatever the task: it does not read, list, search, copy or run anything on what is there, and it never moves a sample into the repository. Three things hold this:
- this rule, which AGENTS.md makes binding on every agent, Codex too;
- `/samples/` in `.gitignore`;
- for Claude Code, deny rules in `.claude/settings.json` on reading it, on writing there and on any shell command that names the folder — as a word of its own, as part of a path, in quotes, after `=` or in a redirection. That includes a command that names it only in passing, such as an edit of a document that mentions it: such an edit goes through the editing tools, not the shell. The rules are narrower than one on the word itself, because canvas's own names hold the word: the release's `samples-page_v<X.Y.Z>.html` and `synthetic-samples_v<X.Y.Z>.<…>`.

A command that walks the whole tree, such as `grep -r` or `find .`, names no folder, and neither the deny rules nor `.gitignore` keep it out of `samples/`. Walk the tracked files instead, with `git grep` and `git ls-files`: `samples/` is never tracked. No folder of the code is called `samples`, at any depth: the deny rules would close it too.

Inside the container these are rules, not an access boundary. So whatever needs the samples is run by the author, and only what holds no handwriting reaches the repository. The tests and the synthetic samples run on strokes that the code draws.
